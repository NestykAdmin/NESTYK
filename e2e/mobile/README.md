# ชุดเทส E2E ของ NESTYK: แอปมือถือ (WebdriverIO + Appium)

ชุดเทสนี้สั่งงานแอป NESTYK ที่ลงอยู่ใน iPhone จำลอง เหมือนที่ผู้ใช้แตะและพิมพ์จริง ตอนนี้มีเทสของหน้าต้อนรับกับหน้า login ชุดแรก 14 ข้อ ซึ่งไม่ใช้ API

โฟลเดอร์นี้มี `package.json` ของตัวเอง และไม่อยู่ใน workspaces ของ monorepo การติดตั้งที่นี่จึงไม่แตะ `package-lock.json` ของราก และ Appium มองเห็นตัวขับของมันเองใน `node_modules` ของโฟลเดอร์นี้

## สิ่งที่ต้องมีก่อนรัน

- เครื่อง Mac ที่มี Xcode และ Node.js 22 ขึ้นไป
- iPhone จำลองเปิดอยู่ 1 เครื่อง พร้อมหน้าต่างของมัน (แอป Device Hub ของ Xcode 27 หรือแอป Simulator ของ Xcode รุ่นก่อน) ถ้าไม่มีหน้าต่าง Appium จะปิดเครื่องจำลองแล้วเปิดใหม่เอง
- แอป NESTYK (`com.nestyk.consumer`) ลงอยู่ในเครื่องจำลองนั้น ชุดเทสไม่ได้ build หรือลงแอปให้
- แอปเป็น build โหมดนักพัฒนา (ตอน build ตั้ง `EXPO_PUBLIC_USE_DEV_AUTH=true` หรือ `EXPO_PUBLIC_APP_ENV=development`) ที่บทบาทตั้งต้นต้องล็อกอิน และยังไม่ได้ต่อ Supabase จริง
  ถ้า build ต่อ Supabase จริง และรันด้วย `E2E_APP_LANGUAGE=en` เทส "rejects an unknown account" จะแดงแบบหมดเวลา เพราะข้อความผิดพลาดจะมาจาก Supabase ส่วนรอบภาษาไทย แอปแสดงคำแปลแทนข้อความผิดพลาดที่ไม่มีตัวอักษรไทย (`packages/i18n/src/error-message.ts`) เทสข้อนี้จึงไม่ช่วยบอกว่า build ต่อ Supabase อยู่
- เทสชุดนี้ไม่ใช้ API และควรรันตอนที่ API ปิดอยู่: ใน build โหมดนักพัฒนา แอปเติมบัญชีนักพัฒนาไว้ในฟอร์มให้เอง ถ้าการแตะของเทสพลาดไปโดนปุ่มเข้าสู่ระบบตอนที่ API เปิดอยู่ แอปจะล็อกอินด้วยบัญชีนั้นจริง (เทสข้อนั้นจะแดง)

## ติดตั้ง

```bash
cd e2e/mobile
npm ci
```

`npm ci` ลงของตาม `package-lock.json` แบบตรงทุกรุ่น: WebdriverIO 9.32.0, Appium 3.8.0, ตัวขับ iOS `appium-xcuitest-driver` 12.15.0 และ TypeScript 5.9.3 (`@wdio/globals` เป็น 9.31.3 เพราะแพ็กเกจนี้ไม่มีรุ่น 9.32.0)

บน Mac ชิป Apple คำสั่งนี้ดาวน์โหลดแพ็กเกจ npm ประมาณ 720 ตัว รวมประมาณ 62 MB จาก registry.npmjs.org และใช้พื้นที่ประมาณ 310 MB ใน `node_modules` (วัดเมื่อ 8 ต.ค. 2026)

## รัน

ต้องรันจากโฟลเดอร์ `e2e/mobile` เสมอ

| คำสั่ง | ทำอะไร |
| --- | --- |
| `npm test` | รันทุกเทส (WebdriverIO เปิดและปิด Appium ให้เอง) |
| `npm run test:smoke` | รันเฉพาะเทสหลักที่ติดป้าย `@smoke` |
| `npm run test:known-bugs` | รันเฉพาะเทสที่ติดป้าย `@known-bug` ถ้าไม่มีเทสที่ติดป้ายนี้ คำสั่งนี้ไม่รันเทสใดและจบด้วยรหัส 0 |
| `npx wdio run ./wdio.conf.ts --spec tests/login-form.spec.ts` | รันไฟล์เดียว |
| `npx wdio run ./wdio.conf.ts --mochaOpts.grep "password"` | รันเฉพาะเทสที่ชื่อมีคำที่ระบุ |
| `npm run typecheck` | ตรวจชนิดข้อมูลของโค้ดเทสด้วย TypeScript |

ครั้งแรกที่รัน Xcode ต้องสร้าง WebDriverAgent (แอปผู้ช่วยในเครื่องจำลองที่รับคำสั่งจาก Appium) จึงใช้เวลานานกว่าครั้งถัดไป

## โครงสร้าง

```
e2e/mobile/
├── wdio.conf.ts             ค่าตั้งของ WebdriverIO และค่าที่ส่งให้ Appium
├── src/
│   ├── config/env.ts        ค่าของเครื่องและของแอป (เปลี่ยนได้ด้วยตัวแปรแวดล้อม)
│   ├── labels/              ข้อความของแอปที่เทสใช้ (ไทย กับอังกฤษ)
│   ├── screens/             Page Object: หน้าจอละไฟล์ รวมวิธีหาและวิธีสั่งงานชิ้นส่วนของหน้านั้น
│   ├── flows/               ขั้นเตรียมที่เทสหลายข้อใช้ร่วมกัน เช่น เปิดแอปไปจนถึงหน้า login
│   └── support/             เปิดปิดแอป รอค่าบนจอ เก็บหลักฐานเมื่อเทสไม่ผ่าน บั๊กที่รู้แล้ว ตัวตรวจเครื่อง และตัวอ่านแป้นพิมพ์
└── tests/                   ไฟล์เทส ไฟล์ละเรื่อง
```

เมื่อเทสไม่ผ่าน โครงสร้างหน้าจอ (XML) กับภาพหน้าจอของตอนนั้นจะอยู่ใน `test-results/` ส่วนข้อความของ Appium อยู่ที่ `logs/wdio-appium.log` (สองโฟลเดอร์นี้ git ไม่เก็บ)

## ข้อตกลงของชุดเทส

- ชื่อเทสเป็นภาษาอังกฤษ คอมเมนต์เป็นภาษาไทย
- ไฟล์เทสไม่หาหรือสั่งงานชิ้นส่วนบนหน้าจอเอง ให้เรียกผ่านไฟล์ใน `src/screens/` ถ้าหน้าจอเปลี่ยน แก้ที่เดียว
- ไฟล์ใน `src/screens/` ไม่ตรวจผล การตรวจ (`expect`) อยู่ในไฟล์เทส
- ทุกเทสเริ่มจากแอปที่เปิดใหม่และล้างข้อมูลในเครื่องแล้ว เพราะแอปจำภาษาที่เลือกกับการล็อกอินไว้ในเครื่อง ขั้นเตรียมนี้เป็นขั้นแรกในตัวเทสเอง ไม่อยู่ใน `beforeEach` เพราะถ้า `beforeEach` พัง Mocha จะข้ามเทสที่เหลือทั้งไฟล์
- ชุดเทสสั่งภาษาของแอปเองตอนเปิด ผลจึงไม่ขึ้นกับภาษาของเครื่องจำลอง และชุดเทสไม่แก้ค่าภาษาของเครื่องจำลอง
- การหาชิ้นส่วนไม่ขึ้นกับภาษาที่แอปแสดง ส่วนการตรวจว่าแอปแสดงภาษาถูกไหม ให้อ่านข้อความจากจอแล้วเทียบกับ `labelsFor(ภาษา)` ในไฟล์เทส
- ไม่รอแบบตายตัว รอเงื่อนไขที่ตรวจได้เสมอ ก่อนแตะหรือพิมพ์ ไฟล์หน้าจอรอให้ชิ้นส่วนหยุดเคลื่อนที่ก่อน และค่าที่เปลี่ยนช้ากว่าคำสั่งให้อ่านด้วย `readUntil` แล้วตรวจด้วย `expect`
- ไม่รันซ้ำเมื่อไม่ผ่าน
- รหัสผ่านที่แอปเติมให้เองต้องไม่ถูกอ่านหรือแสดง เทสนับได้แค่จำนวนตัวอักษร และหลักฐานของเทสที่ไม่ผ่านไม่เก็บค่าของช่องรหัสผ่าน
- บั๊กที่รู้แล้วและรอแก้: เขียนการตรวจตามพฤติกรรมที่ถูกต้อง ครอบด้วย `expectKnownBug` และติดป้าย `@known-bug` ผลรวมจะยังผ่าน และเมื่อบั๊กถูกแก้ เทสข้อนั้นจะแดงเพื่อเตือนให้ลบเครื่องหมายออก

### วิธีหาชิ้นส่วน และข้อยกเว้นชั่วคราว

กฎของชุดเทสคือหาชิ้นส่วนด้วย `testID` ซึ่งไม่เปลี่ยนตามภาษา แต่ที่ commit `0b7682c` และ `a6b3b1e` ชิ้นส่วนของหน้าต้อนรับกับหน้า login ยังไม่มี `testID` ชุดเทสจึงทำ 2 ขั้น (ดู `src/screens/locators.ts`)

1. หาด้วย `testID` ตามชื่อที่เสนอไว้ข้างล่าง
2. ถ้าแอปยังไม่มี `testID` ของชิ้นส่วนนั้น จึงหาด้วยข้อความกำกับจาก `src/labels/` โดยลองทุกภาษาที่ชุดเทสรู้จัก (ไทย กับอังกฤษ)

เมื่อทีมเพิ่ม `testID` ตามชื่อในตาราง ชุดเทสจะใช้เองโดยไม่ต้องแก้ไฟล์ไหน ถ้าทีมใช้ชื่ออื่น ให้แก้ค่า `testId` ของชิ้นส่วนนั้นในไฟล์หน้าจอ

ท้ายผลรันทุกรอบมีบรรทัดที่ขึ้นต้นด้วย `[วิธีหาชิ้นส่วน]` บอกว่าชิ้นส่วนไหนยังต้องหาด้วยข้อความ เมื่อรายการนั้นว่างในรอบที่รันครบทุกเทส ให้ลบขั้นที่ 2 ออก

ข้อจำกัดระหว่างที่ยังใช้ขั้นที่ 2: เทสหาข้อความแจ้งผู้ใช้ด้วยตัวข้อความเอง จึงบอกได้ว่าข้อความนั้นแสดงอยู่ แต่บอกไม่ได้ว่าแสดงผิดที่ (เช่น ข้อความผิดพลาดไปอยู่ในกล่องแจ้งเตือน) ข้อนี้จะตรวจได้เมื่อมี `login.error` กับ `login.notice`

`testID` ที่เสนอ (รูปแบบ `หน้าจอ.ชิ้นส่วน`)

| หน้าจอ | testID |
| --- | --- |
| หน้าต้อนรับ | `preload.enter` |
| หน้า login | `login.email`, `login.password`, `login.togglePassword`, `login.forgot`, `login.submit`, `login.google`, `login.facebook`, `login.apple`, `login.signup`, `login.language`, `login.error`, `login.notice` |
| แผ่นเลือกภาษา | `language.option.th`, `language.option.en`, `language.option.zh`, `language.option.ja` |

## ข้อควรรู้ของเครื่องจำลองที่ใช้เทส

### แป้นพิมพ์ของเครื่องจำลองกับช่องรหัสผ่าน

ช่องรหัสผ่านแบบซ่อนตัวอักษรรับเฉพาะตัวอักษรที่มีปุ่มบนแป้นพิมพ์ที่เครื่องจำลองใช้อยู่ ตัวอักษรอื่นหายไปโดยไม่มีข้อความแจ้ง ส่วนช่องรหัสผ่านหลังกดปุ่มตาให้แสดงตัวอักษรรับครบทั้งตัวอักษรไทยและอังกฤษ ไม่ว่าแป้นพิมพ์จะเป็นภาษาไหน

ผลจริงบน iPhone 18 Pro จำลอง iOS 27 เมื่อ 8 ต.ค. 2026 (ให้ Appium พิมพ์ข้อความละ 6 ตัวลงช่องรหัสผ่านแบบซ่อนตัวอักษรของหน้า login ทุกครั้งเริ่มจากแอปที่เพิ่งเปิดและล้างข้อมูลแล้ว)

| แป้นพิมพ์ที่ใช้อยู่ | พิมพ์ `abcdef` | พิมพ์ `กขคงจบ` |
| --- | --- | --- |
| ไทย (ขั้นที่ 29) | เข้าช่อง 0 ตัว | เข้าครบ 6 ตัว |
| อังกฤษ (ขั้นที่ 30) | เข้าครบ 6 ตัว | เข้าช่อง 0 ตัว |

- ตัวเลขกับขีด: หน้าตัวอักษรของแป้นพิมพ์ไทยไม่มีปุ่มตัวเลขกับขีด (มีปุ่ม "ตัวเลข" ไว้สลับหน้า) แต่ตัวเลขกับขีดเข้าช่องแบบซ่อนได้ครบทั้งเมื่อใช้แป้นพิมพ์ไทย (ขั้นที่ 27 กับ 28) และแป้นพิมพ์อังกฤษ (ขั้นที่ 31: ชุดเทสผ่านครบ 14 ข้อ และเทสปุ่มตาอ่านรหัสผ่านทดลองกลับได้ตรงทุกตัว)
- ช่องอีเมลรับตัวอักษรภาษาอังกฤษครบแม้ใช้แป้นพิมพ์ไทย (ขั้นที่ 26 กับ 27) ส่วนตัวอักษรไทยในช่องอีเมลยังไม่ได้ลอง
- ตำแหน่งของแป้นพิมพ์ไม่ใช่ตัวแยกผล: ตอนใช้แป้นพิมพ์ไทย ตัวอักษรภาษาอังกฤษหายทั้งตอนที่แป้นพิมพ์อยู่นอกจอ (ขั้นที่ 26 กับ 29) และตอนที่แป้นพิมพ์ขึ้นมาอยู่บนจอแล้วหลังพิมพ์ (ขั้นที่ 27) ส่วนแป้นพิมพ์อังกฤษได้ลองเฉพาะตอนที่แป้นพิมพ์อยู่นอกจอ (ขั้นที่ 30)
- ยังไม่ถือเป็นบั๊กของแอป แต่ข้อนี้เป็นการอนุมาน: ผู้ใช้ที่พิมพ์ผ่านปุ่มบนแป้นพิมพ์ได้ตัวอักษรของปุ่มที่กดอยู่แล้ว ส่วนการวางข้อความ (paste) การเติมรหัสผ่านอัตโนมัติ และช่องรหัสผ่านของแอปอื่นยังไม่ได้ลอง

สิ่งที่ชุดเทสทำเพราะเรื่องนี้

- รหัสผ่านทดลอง (`TEST_PASSWORD` ใน `tests/login-form.spec.ts`) ใช้แค่ตัวเลขกับขีด จึงผ่านได้ทั้งแป้นพิมพ์ไทยและอังกฤษ (ขั้นที่ 28 กับ 31)
- เทสที่ต้องพิมพ์ตัวอักษรภาษาอังกฤษลงช่องแบบซ่อน ต้องรันกับเครื่องจำลองที่ใช้แป้นพิมพ์อังกฤษ
- ถ้าช่องรหัสผ่านแบบซ่อนได้ตัวอักษรน้อยกว่าที่พิมพ์ `typePassword` ของหน้า login จะพิมพ์บรรทัดที่ขึ้นต้นด้วย `[แป้นพิมพ์]` บอกแป้นพิมพ์ที่ขึ้นอยู่ตอนนั้น (`src/support/keyboard.ts`)
  - บรรทัดนี้อยู่ในผลของ WebdriverIO ระหว่างที่เทสข้อนั้นรัน (อยู่ก่อนสรุปผลของเทส) ไม่เปลี่ยนผลเทส และไม่แสดงข้อความที่พิมพ์ ให้ดูบรรทัดนี้ก่อนสรุปว่าแอปผิด
  - ถ้าบรรทัดบอกว่าไม่มีปุ่มตัวอักษรไทยหรืออังกฤษ แป้นพิมพ์อาจค้างอยู่หน้าตัวเลข ให้ดูภาษาของแป้นพิมพ์จากไฟล์ค่าตั้งตามข้างล่าง

ดูว่าเครื่องจำลองใช้แป้นพิมพ์อะไรอยู่

- ดูจากไฟล์ค่าตั้งของเครื่องจำลอง (อ่านอย่างเดียว ไม่แก้ไฟล์) รหัสเครื่องจำลองดูได้จาก `xcrun simctl list devices booted`

  ```bash
  plutil -extract KeyboardsCurrentAndNext xml1 -o - ~/Library/Developer/CoreSimulator/Devices/<รหัสเครื่องจำลอง>/data/Library/Preferences/com.apple.keyboard.preferences.plist
  ```

  ค่าแรกในรายการคือแป้นพิมพ์ที่ใช้อยู่: `en_US@sw=QWERTY;hw=Automatic` คือแป้นพิมพ์อังกฤษ ส่วน `th_TH@sw=Thai;hw=Automatic` คือแป้นพิมพ์ไทย ข้อนี้อนุมานจาก 2 ครั้งที่ค่าแรกตรงกับแป้นพิมพ์ที่ขึ้นจริง (ขั้นที่ 29 ไทย ขั้นที่ 30 อังกฤษ) และค่าในไฟล์อาจยังไม่เปลี่ยนทันทีหลังสลับ
- ดูบนจอ: แตะช่องรหัสผ่านของแอป (ช่องที่เรื่องนี้เกิด การแตะไม่ได้แสดงรหัสผ่าน) ถ้าแป้นพิมพ์ขึ้นและแถวบนเป็น q w e r t y คือแป้นพิมพ์อังกฤษ ถ้าแป้นพิมพ์ไม่ขึ้นบนจอ เช่น ตอนเปิด Simulate Hardware Keyboard ไว้ ให้ดูจากไฟล์แทน
  - ช่องอีเมลใช้แป้นพิมพ์แบบอีเมล (`keyboardType="email-address"` ใน `apps/consumer-app/app/login.tsx`) จึงอาจขึ้นแป้นพิมพ์ไม่เหมือนช่องรหัสผ่าน (อนุมาน ในขั้นที่ 29 กับ 30 สองช่องขึ้นภาษาเดียวกัน)

สลับเป็นแป้นพิมพ์อังกฤษ

- แตะช่องกรอกในแอปให้แป้นพิมพ์ขึ้น (ขั้นที่ 30 สลับจากช่องอีเมล) แตะค้างที่ปุ่มลูกโลกใต้แป้นพิมพ์ด้านซ้าย แล้วเลือกแป้นพิมพ์อังกฤษ
- เมื่อเทียบกับสำเนาที่เก็บไว้ก่อนขั้นที่ 29 การสลับนี้เปลี่ยน 3 ค่าในไฟล์ `com.apple.keyboard.preferences` (`KeyboardsCurrentAndNext`, `KeyboardLastUsed`, `KeyboardLastUsedForLanguage`) ไฟล์นี้เป็นค่าตั้งของเครื่องจำลอง ไม่ใช่ของแอป แป้นพิมพ์อังกฤษจึงยังอยู่แม้ล้างข้อมูลของแอปก่อนทุกข้อของการทดลองในขั้นที่ 30 และวันถัดมาค่ายังเป็นอังกฤษ (ขั้นที่ 31 ช่วงนั้นเครื่องจำลองเปิดอยู่ตลอด) ส่วนหลังปิดเปิดเครื่องจำลองยังไม่ได้ลอง
- ถ้าในรายการไม่มีแป้นพิมพ์อังกฤษ ให้เพิ่มในแอปการตั้งค่าของเครื่องจำลอง หัวข้อแป้นพิมพ์ (ยังไม่ได้ลองบนเครื่องที่ใช้เทส เพราะเครื่องนั้นมีแป้นพิมพ์อังกฤษอยู่แล้ว)

วิธีที่ลองแล้วไม่ได้ผล (ขั้นที่ 29): ส่งตัวเลือก `-AppleKeyboards` ให้แอปตอนเปิด และเขียนค่าแป้นพิมพ์ 4 ค่าแบบเดียวกับคำสั่ง `mobile: configureLocalization` ของ Appium (appium-ios-simulator 10.7.0 ฟังก์ชัน `configureLocalization`) คือ `AppleKeyboards` ในค่าตั้งส่วนกลาง กับ `KeyboardsCurrentAndNext` `KeyboardLastUsed` `KeyboardLastUsedForLanguage` ในไฟล์ `com.apple.Preferences` แป้นพิมพ์ยังเป็นไทยทั้ง 2 วิธี ส่วนการสลับด้วยปุ่มลูกโลกในขั้นที่ 30 ไม่ได้เปลี่ยนค่าทั้ง 4 นี้เลย

### ค่าอื่นของเครื่องจำลอง

- ค่า Simulate Hardware Keyboard ของ Device Hub (เมนู Device > Keyboard) Appium ปรับเองไม่ได้ เพราะ macOS ไม่ให้เขียนไฟล์ค่าตั้งของ Device Hub ผลการพิมพ์ในขั้นที่ 26 กับ 27 ได้เท่ากัน (ก่อนขั้นที่ 27 Aof ปิดค่านี้เองที่ Device Hub ส่วนตอนขั้นที่ 26 ไม่ทราบว่าค่านี้เปิดอยู่หรือไม่)

## ที่มาของข้อมูลจากเครื่องจริงในคอมเมนต์

คอมเมนต์ในโค้ดและหัวข้อในไฟล์นี้ที่อ้าง "ขั้นที่ 17" ถึง "ขั้นที่ 31" หมายถึงการรันบนเครื่องที่ใช้เทส (Mac ชิป Apple, Xcode 27, iPhone 18 Pro จำลอง iOS 27) เมื่อ 6 ถึง 9 ต.ค. 2026 ซึ่งให้ Appium เปิดแอปแล้วอ่านหน้าจอจริง (ขั้นที่ 26 คือการรันชุดเทสนี้ครั้งแรก ขั้นที่ 27 คือการทดลองพิมพ์ ขั้นที่ 28 คือการรันชุดเทสหลังเปลี่ยนรหัสผ่านทดลอง ขั้นที่ 29 กับ 30 คือการพิสูจน์เรื่องแป้นพิมพ์ ขั้นที่ 31 คือการรันชุดเทสซ้ำบนแป้นพิมพ์อังกฤษ) ผลสรุปอยู่ในบันทึกงาน QA (เอกสาร `claude/nestyk-qa-setup-and-plan.md` ของโปรเจกต์ QA NESTYK ข้อ 10, 12 และ 13) ส่วนไฟล์ผลดิบอยู่ในโฟลเดอร์ `Claude outputs` ของเครื่องนั้น ซึ่ง git ไม่เก็บ

## ตัวแปรแวดล้อม

ไม่ต้องตั้งถ้าเทสกับ iPhone จำลองที่เปิดอยู่เครื่องเดียวตามค่าเริ่มต้น

| ชื่อ | ค่าเริ่มต้น | ใช้ทำอะไร |
| --- | --- | --- |
| `E2E_IOS_UDID` | iPhone จำลองที่เปิดอยู่ (ต้องมีเครื่องเดียว) | รหัสประจำเครื่องจำลองที่จะใช้เทส |
| `E2E_IOS_BUNDLE_ID` | `com.nestyk.consumer` | รหัสประจำแอป |
| `E2E_APP_LANGUAGE` | `th` | ภาษาที่ชุดเทสสั่งให้แอปใช้ และภาษาของข้อความที่เทสคาด (`th` หรือ `en`) |
| `E2E_EXPECT_DEV_AUTH` | `true` | แอปเป็น build โหมดนักพัฒนาหรือไม่ (มีผลกับเทสค่าตั้งต้นของช่องกรอก) |
| `E2E_DEV_LOGIN_EMAIL` | บัญชีนักพัฒนาของทีม | อีเมลที่แอปเติมให้ในโหมดนักพัฒนา |
| `E2E_APPIUM_PORT` | `4723` | พอร์ตของ Appium ในเครื่องนี้ |
| `E2E_WAIT_MS` | `15000` | เวลาสูงสุดที่รอให้หน้าจอเปลี่ยนตามที่คาด (มิลลิวินาที) |
| `E2E_APP_READY_WAIT_MS` | `40000` | เวลาสูงสุดที่รอให้แอปเปิดจนพร้อม (มิลลิวินาที) |
| `E2E_DEVICE_CHECK` | `false` | `true` = ลองวิธีหาชิ้นส่วนหลายแบบตอนเริ่มรอบแล้วพิมพ์ผล (ใช้ตรวจเครื่องใหม่) |
| `E2E_WDIO_LOG_LEVEL` | `warn` | ระดับข้อความของ WebdriverIO ที่เก็บลง `logs/` |
