# ทะเบียนบั๊กของ NESTYK (ฝั่ง QA)

บั๊กที่ QA พบ ทั้งที่ยังเปิดอยู่และที่ปิดแล้ว 1 แถวต่อ 1 บั๊ก ไฟล์นี้เป็นที่เดียวที่เก็บรายการและสถานะของบั๊ก
ที่อื่น (เหตุผลของ `test.fail` ไฟล์รายงานถึงทีม และ README ของชุดเทส) ให้อ้างเลขบั๊กจากไฟล์นี้ ไม่เก็บสถานะซ้ำ

## วิธีใช้

- เลขบั๊ก: `API-NNN` (API), `WEB-NNN` (เว็บ), `MOB-NNN` (แอปมือถือ) เรียงตามลำดับที่ลงทะเบียน เลขที่ใช้แล้วไม่นำกลับมาใช้กับบั๊กอื่น (ยกเว้น `MOB-001` ซึ่งโค้ดเทสใช้เลขนี้มาก่อนมีทะเบียน จึงมีแถวทีหลัง `MOB-002`)
- สถานะมี 6 ค่า: สงสัย, ยืนยันแล้ว, dev แก้แล้ว, ตรวจซ้ำผ่าน, ไม่ใช่บั๊ก, พักไว้ คนเปลี่ยนสถานะคือ Aof (QA) เท่านั้น
- ไม่ลบแถว บั๊กที่ปิดแล้วให้เปลี่ยนสถานะ และแก้วันที่ในช่อง "อัปเดตล่าสุด"
- "อาการที่ใช้จับคู่" คือสิ่งที่เทสเห็นจริงตอนบั๊กยังอยู่ ใช้ตอนอ่านผลรัน: ข้อที่ติดป้าย `@known-bug` แล้วล้ม ต้องล้มด้วยอาการนี้จึงนับเป็นบั๊กเดิม ถ้าล้มด้วยอาการอื่น ให้ถือเป็นเรื่องใหม่ แถวที่ไม่มีเทสเคยเห็นอาการ ช่องนี้ขึ้นต้นว่า "อ่านจากโค้ด"
  - ชุด `e2e/web-api` (Playwright): ข้อ `@known-bug` ที่ล้มตามคาดขึ้นเครื่องหมาย ✘ ในรายการ แต่ตัวรันนับรวมเป็น passed และไฟล์ผลแบบข้อความไม่พิมพ์ error ของข้อนั้น เครื่องหมาย ✘ จึงบอกไม่ได้ว่าล้มด้วยอาการไหน ให้เปิดดูในรายงาน HTML ของรอบนั้น (ที่ `e2e/web-api`: `npm run report` สำหรับชุด api, `npx playwright show-report playwright-report-web-ui` และ `npx playwright show-report playwright-report-web-ui-th` สำหรับชุดเว็บ) รายงานเก็บเฉพาะรอบล่าสุด ต้องเปิดก่อนรันซ้ำ
  - ชุด `e2e/mobile`: ข้อ `@known-bug` ที่บั๊กยังอยู่ขึ้น ✓ และผลรันพิมพ์ `[known-bug <id>] ยังพบอยู่`
  - ถ้าขึ้น "Expected to fail, but passed" (Playwright) หรือ `[known-bug <id>] ไม่พบบั๊กนี้แล้ว` (มือถือ) แปลว่ารอบนั้นไม่เห็นอาการแล้ว ให้ดูค่าตั้งของรอบนั้นก่อนเปลี่ยนสถานะ: WEB-001 ดู `EXPO_PUBLIC_ALLOW_DEV_ROLE_GRANT` ของเว็บที่ใช้รัน และ WEB-002 เทียบ `E2E_WEB_SIGN_OUT_TO` ของชุดเทสกับ `EXPO_PUBLIC_WEB_SIGN_OUT_TO` ของเว็บว่าตั้งตรงกันหรือไม่
- จุดในเทสที่ผูกกับบั๊ก ดูได้ด้วยคำสั่งนี้ที่รากของ repo (อ่านอย่างเดียว)
  `grep -rnE --include="*.ts" --exclude-dir=node_modules "test\.fail\(|@known-bug|expectKnownBug\(|knownBug:" e2e/web-api e2e/mobile`
  - 12 พ.ย. 2026 ที่ qa/e2e `9190108` รันบนเครื่อง Aof ได้ 27 บรรทัด: 16 บรรทัดเป็นของ 5 บั๊กแรกในตาราง (รวมคอมเมนต์หัวไฟล์ 2 บรรทัดของ MOB-002 ใน `agent-session.spec.ts`) อีก 11 บรรทัดไม่ใช่บั๊ก คือ ตัวช่วย `known-bug.ts` 3 บรรทัด (7, 25, 38), โครงใน `agent-contracts.spec.ts` 4 บรรทัด (283, 324, 326, 327), โครงใน `signup-reset-errors.spec.ts` 3 บรรทัด (47, 53, 157) และคอมเมนต์ใน `lead-room-limits.write.spec.ts` 1 บรรทัด (22)
  - โครงใน 2 ไฟล์นั้นเปิดใช้ด้วยการใส่ `knownBug: '...'` ในแถวข้อมูล ตอนนี้ยังไม่มีแถวไหนใส่ เวลาตรวจให้เทียบรายชื่อบรรทัด (ไฟล์กับเลขบรรทัด) กับรายการในข้อบน ไม่เทียบแค่จำนวน เพราะคำสั่งนี้จับคอมเมนต์ด้วย และบรรทัดที่เพิ่มกับที่ถูกถอดอาจหักล้างกันจนจำนวนเท่าเดิม บรรทัดที่ไม่อยู่ในรายการต้องเป็นคอมเมนต์ หรือมีแถวในตารางรองรับ
- ไฟล์รายงานใต้ `Claude outputs/` git ไม่เก็บ (`.gitignore` ของ repo) จึงอยู่บนเครื่องของ QA เท่านั้น เอกสารชื่อเดียวกันอยู่ใต้ `claude/` ในโปรเจกต์ QA NESTYK บน claude.ai
- ทะเบียนเก็บเฉพาะบั๊กที่ทำซ้ำได้จากผลรันหรือเทสด้วยมือ ข้อสังเกตจากการอ่านโค้ดที่ยังไม่มีผลรันยืนยัน (เช่น รายการรีวิวระบบบัญชี 2 พ.ย. 2026) อยู่ในไฟล์ของตัวเอง ไม่ลงทะเบียนจนกว่าจะทำซ้ำได้ ยกเว้นเรื่องที่ทีมยืนยันหรือแก้แล้ว (ตอนนี้คือ API-006 และ API-008)
- บั๊กที่ปิดแล้วไม่มีเครื่องหมายในเทส ช่อง "เทสที่ผูก" ของแถวเหล่านั้นคือเทสที่กันบั๊กกลับมา ถ้าเทสข้อนั้นแดง ให้ดูแถวนี้ก่อนเปิดเลขใหม่
- แถวเรียงตามลำดับที่ลงทะเบียน: 5 แถวแรกคือบั๊กที่ยังมีเครื่องหมายในเทส แถวถัดไป (เพิ่ม 12 พ.ย. 2026) คือบั๊กย้อนหลัง และเรื่องที่ยังเปิดอยู่แต่ไม่มีเครื่องหมายในเทส
