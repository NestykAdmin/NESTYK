## สาเหตุ

ยืนยันตามที่ QA เขียน เดิมใช้ตัวแปร `skipPlacesSearch` แบบ true/false เพื่อบอก effect ค้นสถานที่ว่า "รอบหน้าอย่าค้น" แต่ effect ใช้ค่านี้หมดไปตั้งแต่รอบ render ที่ชื่อโครงการยังว่าง พอรอบถัดไปชื่อเดิมถูกใส่เข้ามา จึงไม่มีอะไรกันไว้ และค้นหลังรอ 300 ms

ปัญหาจริงคือ flag แบบ true/false ขึ้นกับว่า effect จะรันกี่รอบและรันตอนไหน ซึ่งคุมไม่ได้

## สิ่งที่แก้

### 1. เปลี่ยนจาก "ข้ามรอบหน้า" เป็น "จำชื่อที่แอปใส่ให้เอง"

- เปลี่ยน `skipPlacesSearch` (true/false) เป็น `appliedPlaceName` ที่เก็บชื่อโครงการที่แอปใส่ลงช่องเอง (บรรทัด 428)
- ตอนเปิดหน้าแก้ เก็บชื่อโครงการเดิมไว้ (บรรทัด 630)
- effect ค้นสถานที่ (บรรทัด 958-1007) เทียบชื่อในช่องกับชื่อที่จำไว้ทุกครั้งที่รัน ผ่านฟังก์ชันใหม่ `placesSearchAction` (`packages/feature-listing/src/components/places-search-gate.ts`)
  - ชื่อสั้นกว่า 2 ตัวอักษร: ล้างรายการแนะนำ (เหมือนเดิม)
  - ชื่อตรงกับที่แอปใส่ให้เอง: ไม่ค้น
  - ชื่ออื่น: ค้นตามปกติหลังรอ 300 ms (เหมือนเดิม)
- ผลคือไม่ว่า effect จะรันกี่รอบ ก็ไม่ค้นชื่อเดิมตอนเปิดหน้าแก้ และผู้ใช้แก้ชื่อเมื่อไรก็ค้นได้ทันที

### 2. บั๊กแฝงตอนเลือกสถานที่จากรายการแนะนำ (QA ไม่ได้แจ้ง)

- `handleSelectPlace` (บรรทัด 1295-1314) ใช้ flag ตัวเดิมเพื่อไม่ให้ค้นชื่อสถานที่ที่เพิ่งเลือก
- ถ้าชื่อสถานที่ที่เลือก **ตรงกับข้อความที่พิมพ์ไว้พอดี** ชื่อในช่องไม่เปลี่ยน effect จึงไม่รัน flag ค้างอยู่ แล้วไปกินการพิมพ์ครั้งถัดไปของผู้ใช้ (พิมพ์ต่อแล้วไม่มีรายการแนะนำขึ้น)
- หลังแก้: จำชื่อสถานที่ที่เลือก (บรรทัด 1299, 1306) แทน flag พิมพ์ต่อเมื่อไรก็ค้นได้
- ถ้าโหลดรายละเอียดสถานที่ไม่สำเร็จ ก็ไม่มี flag ค้างเหมือนเดิมแล้ว

### 3. ปุ่ม "Search on map instead"

- กดปุ่มนี้ (บรรทัด 2633-2637) จะล้างชื่อที่จำไว้ก่อนกลับไปโหมดค้นหา เพื่อให้ค้นชื่อในช่องทันทีเหมือนเดิม เพราะผู้ใช้เป็นคนกดเอง
- ไม่ได้เปลี่ยนพฤติกรรมเดิม ใส่ไว้กันไม่ให้การแก้ข้อ 1 ทำให้ปุ่มนี้ทำงานต่างจากเดิม

## ฝาก QA ตรวจ

1. รัน `e2e/web-api/tests/web-ui-write/agent-rooms.write.spec.ts` ข้อ "opening the room editor does not search places by itself" ควรขึ้น "Expected to fail, but passed" แล้วถอดป้าย `@known-bug`
2. เทสข้อสร้างห้องในไฟล์เดียวกันควรยังผ่านเหมือนเดิม
3. **แอปมือถือ:** หน้าแก้ห้องบนมือถือใช้ component เดียวกัน อาการเดิมน่าจะเกิดบนมือถือด้วย และน่าจะหายไปพร้อมกัน ฝากลองเปิดหน้าแก้บนมือถือด้วย
4. **บั๊กแฝง:** หน้าสร้างห้อง พิมพ์ชื่อโครงการให้ตรงกับชื่อในรายการแนะนำ เลือกรายการนั้น แล้วพิมพ์ต่อ ต้องมีคำขอ `places` และรายการแนะนำขึ้น
5. **ปุ่มสลับโหมด:** หน้าแก้ห้อง กด "Enter location manually" แล้วกด "Search on map instead" ต้องค้นชื่อในช่องทันที (เหมือนก่อนแก้)

## สิ่งที่ต่างจากเดิมที่ควรรู้

- หน้าแก้ห้อง ถ้าผู้ใช้แก้ชื่อแล้วพิมพ์กลับเป็นชื่อเดิมตรงตัว จะไม่ค้น เพราะเป็นชื่อเดียวกับที่บันทึกไว้แล้ว ส่วนชื่ออื่นค้นตามปกติ
