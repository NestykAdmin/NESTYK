## ที่มาของบั๊ก

ยืนยันตามที่ QA เขียน บั๊กนี้มาจากการแก้เรื่อง "Failed to fetch" เมื่อ 6 พ.ย. (`docs/qa-fixes/2026-11-06-web-flow-bugs-reply.md` เรื่องที่ 3) การแก้ครั้งนั้นทำให้ error เครือข่ายใช้ "ข้อความสำรอง" ที่แต่ละหน้าส่งมาเสมอ ซึ่งถูกต้องสำหรับหน้าส่วนใหญ่ แต่หน้า login ส่งข้อความสำรองเป็น "อีเมลหรือรหัสผ่านไม่ถูกต้อง" ไว้สำหรับ **ทุก** error

## ปัญหาที่ลึกกว่าที่ QA แจ้ง

### 1. หน้าภาษาไทยเป็นแบบนี้มาก่อน 6 พ.ย. แล้ว

ก่อนการแก้เมื่อ 6 พ.ย. error เครือข่ายมีข้อความภาษาอังกฤษ ("Failed to fetch") ซึ่งไม่ตรงกับภาษาของหน้าภาษาไทย จึงถูกแทนด้วยข้อความสำรองอยู่แล้ว หน้าภาษาไทยจึงขึ้น "อีเมลหรือรหัสผ่านไม่ถูกต้อง" มาตั้งแต่ก่อน `fc1a351` การแก้เมื่อ 6 พ.ย. แค่ทำให้หน้าภาษาอังกฤษเป็นแบบเดียวกัน

ไม่ใช่แค่เน็ตหลุด error อะไรก็ตามที่ไม่ได้เป็นภาษาไทย (เช่น API ตอบ 500 เป็นภาษาอังกฤษ, captcha ไม่ผ่าน, ยังไม่ได้ยืนยันอีเมล) หน้าภาษาไทยจะขึ้นว่ารหัสผิดทั้งหมด

### 2. ตัวจัดการ login ทิ้ง "รหัส error" ของ Supabase

ใน `AuthContext.tsx` (`signIn`) ตอน Supabase ปฏิเสธการ login โค้ดเดิมสร้าง error ใหม่ที่มีแค่ข้อความ (`throw new Error(error?.message)`) ทำให้ข้อมูลที่ Supabase ส่งมาหายไปหมด

- รหัส `invalid_credentials` ที่บอกว่ารหัสผิดจริง
- ชื่อ `AuthRetryableFetchError` ที่บอกว่าเชื่อม Supabase ไม่ได้

ผลคือหน้า login แยกไม่ออกเลยว่ารหัสผิดจริง หรือเชื่อมต่อไม่ได้ และการแก้เมื่อ 6 พ.ย. ก็ไม่ครอบกรณีเชื่อม Supabase ไม่ได้ ตอนนั้นหน้าภาษาอังกฤษยังขึ้น "Failed to fetch" ดิบอยู่ ส่วนหน้าภาษาไทยขึ้นว่ารหัสผิด

### 3. หน้าอื่นที่มีปัญหาแบบเดียวกัน (QA ข้อ 2)

- **หน้าสมัคร ขั้นใส่รหัส 6 หลัก** (`register.tsx:151`): ใช้ "รหัสไม่ถูกต้อง" เป็นข้อความสำรองของทุก error เน็ตหลุดก็บอกว่ารหัสผิด
- **หน้าลืมรหัสผ่าน** (`reset-password.tsx:96`, `:135`): ใช้ข้อความ "สมัครสมาชิกไม่สำเร็จ กรุณาลองอีกครั้ง หากสร้างบัญชีแล้ว ให้กลับไปเข้าสู่ระบบ" ซึ่งเป็นข้อความของหน้าสมัครสมาชิก ไม่เกี่ยวกับการรีเซ็ตรหัส
- จุดอื่นในหน้าสมัคร ใช้ "สมัครสมาชิกไม่สำเร็จ…" ซึ่งเป็นข้อความกลางของหน้านั้นอยู่แล้ว ไม่ได้แก้

## สิ่งที่แก้

1. **`lib/auth/auth-error.ts` (ใหม่):** รวมกฎการแยกสาเหตุไว้ที่เดียว
   - `signInFailure`: error ที่ `signIn` โยน ข้อความเหมือนเดิม แต่เก็บชื่อ, status และรหัสของ Supabase ไว้ด้วย
   - `isInvalidCredentials`: เป็นรหัสผิดจริงเมื่อ Supabase ส่งรหัส `invalid_credentials` (หรือข้อความรหัสผิดของ Supabase/dev login เมื่อไม่มีรหัส)
   - `isInvalidOtp`: รหัส 6 หลักผิดหรือหมดอายุจริงเมื่อ Supabase ส่งรหัส `otp_expired`
2. **`AuthContext.tsx:264`:** `signIn` โยน `signInFailure(error)` แทน error ที่มีแค่ข้อความ
3. **`login.tsx:126`:** ขึ้น "อีเมลหรือรหัสผ่านไม่ถูกต้อง" เฉพาะเมื่อรหัสผิดจริง กรณีอื่นใช้ `localizedError(e, t.common.errorGeneric, locale)`
   - error ที่มีข้อความเป็นภาษาของหน้าอยู่แล้ว (เช่น หน้าภาษาอังกฤษเจอ "Email not confirmed") ยังแสดงข้อความนั้นเหมือนเดิม
   - error เครือข่ายทุกแบบ (API sync ล้ม, เชื่อม Supabase ไม่ได้) และข้อความที่เป็นคนละภาษากับหน้า ใช้ข้อความกลาง
4. **`register.tsx:151`:** ขึ้น "รหัสไม่ถูกต้อง" เฉพาะเมื่อรหัสผิดหรือหมดอายุจริง กรณีอื่นใช้ข้อความกลาง
5. **`reset-password.tsx:96`, `:135`:** เปลี่ยนข้อความสำรองเป็นข้อความกลาง ส่วนข้อความ "ลิงก์ใช้ไม่ได้" ตอนลิงก์หมดอายุยังเหมือนเดิม

ข้อความที่ใช้ (มีครบ 4 ภาษาอยู่แล้ว)

| key | ไทย | อังกฤษ |
| --- | --- | --- |
| `common.errorGeneric` | เกิดข้อผิดพลาด กรุณาลองอีกครั้ง | Something went wrong. Please try again. |
| `mobile.auth.invalidCredentials` | อีเมลหรือรหัสผ่านไม่ถูกต้อง | Invalid email or password |
| `mobile.auth.otpInvalid` | รหัสไม่ถูกต้อง กรุณาตรวจสอบแล้วลองอีกครั้ง | That code is not correct. Check it and try again. |

## ผลกระทบ

- **ทั้งเว็บและแอปมือถือ:** หน้า login, สมัคร และลืมรหัสผ่านใช้ไฟล์เดียวกัน
- **รหัสผิดจริง:** ยังขึ้น "อีเมลหรือรหัสผ่านไม่ถูกต้อง" เหมือนเดิม หน้าภาษาอังกฤษเดิมเคยขึ้นข้อความดิบของ Supabase "Invalid login credentials" ตอนนี้จะขึ้น "Invalid email or password" ของเราแทน
- **captcha ไม่ผ่าน, ยังไม่ได้ยืนยันอีเมล:** หน้าภาษาไทยเปลี่ยนจาก "รหัสผิด" เป็นข้อความกลาง (ถูกต้องกว่าเดิม แต่ยังไม่บอกสาเหตุเจาะจง) หน้าภาษาอังกฤษแสดงข้อความของ Supabase เหมือนเดิม
- **ไม่เปลี่ยน:** พฤติกรรมเรื่องเครือข่ายที่แก้เมื่อ 6 พ.ย. ในหน้าอื่น (`packages/i18n/src/error-message.ts` ไม่ได้แก้), ปุ่ม Google/Facebook, การ sync profile และการ sign out ตอน sync ล้ม

## ฝาก QA ตรวจ

1. **ที่ QA แจ้ง:** ให้เว็บชี้ API ที่เรียกไม่ได้ แล้วล็อกอินด้วยรหัสที่ถูก ต้องขึ้นข้อความกลาง ไม่ใช่รหัสผิด (ทั้งหน้าไทยและอังกฤษ) และยังไม่ได้เข้าสู่ระบบ
2. **รหัสผิดจริง:** ใส่รหัสผิดตอน API ปกติ ต้องขึ้น "อีเมลหรือรหัสผ่านไม่ถูกต้อง" / "Invalid email or password"
3. **เชื่อม Supabase ไม่ได้:** บล็อกคำขอไป Supabase ในเบราว์เซอร์ (`*.supabase.co`) แล้วล็อกอิน ต้องขึ้นข้อความกลาง
4. **หน้าสมัคร ขั้นรหัส 6 หลัก:** ใส่รหัสผิดต้องขึ้น "รหัสไม่ถูกต้อง…" ถ้าปิดเน็ตแล้วกดยืนยันต้องขึ้นข้อความกลาง
5. **หน้าลืมรหัสผ่าน:** ทำให้ส่งไม่สำเร็จ (เช่น ปิดเน็ต) ต้องขึ้นข้อความกลาง ไม่ใช่ข้อความ "สมัครสมาชิกไม่สำเร็จ…"
6. **แอปมือถือ:** ลองข้อ 1-2 บนมือถือด้วย เพราะใช้หน้าเดียวกัน
7. QA บอกว่าจะเพิ่มเทสอัตโนมัติที่ทำให้ `POST /auth/sync` ล้ม ข้อความที่ควรตรวจคือ `common.errorGeneric` ตามตารางข้างบน

## หมายเหตุ
