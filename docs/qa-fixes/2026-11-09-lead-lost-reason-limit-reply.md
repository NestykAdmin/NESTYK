## สิ่งที่แก้

### 1. ช่องเหตุผลหยุดรับที่ 500 ตัว

- เพิ่มค่าคงที่ `LOST_REASON_MAX = 500` (บรรทัด 135) เท่ากับเพดานใน `parseLostReason` ของ API (`apps/api/src/agent/leads/agent-leads.service.ts`)
- ช่องเหตุผลตั้ง `maxLength={LOST_REASON_MAX}` (บรรทัด 717) พิมพ์หรือวางข้อความเกิน 500 ตัวไม่ได้ ถ้าวางข้อความยาว ระบบจะตัดเหลือ 500 ตัวแรก

### 2. ตัวนับตัวอักษร

- แสดง `จำนวนที่พิมพ์/500` ชิดขวาใต้ช่องเหตุผล (บรรทัด 719-721) เช่น `123/500` เปลี่ยนทุกครั้งที่พิมพ์
- เป็นตัวเลขอย่างเดียว จึงไม่ต้องเพิ่มคำแปล

### 3. หัวข้อความตอนเปลี่ยนสถานะไม่สำเร็จ

- เปลี่ยนจาก `c.loadError` ("Could not load data") เป็น `c.saveError` ที่มีอยู่แล้วครบ 4 ภาษา (บรรทัด 408)

  | ภาษา | ข้อความ |
  | --- | --- |
  | ไทย | บันทึกไม่สำเร็จ |
  | อังกฤษ | Could not save lead |
  | จีน | 保存失败 |
  | ญี่ปุ่น | 保存できません |

## ผลกระทบ

- **ทั้งเว็บและแอปมือถือ:** หน้ารายละเอียดลีดใช้ component เดียวกัน (`AgentLeadDetailBody` ใน `app/index.tsx`) ช่องเหตุผลและตัวนับจึงเปลี่ยนทั้งสองที่
- **การเปลี่ยนสถานะทั้งสองทาง:** หัวข้อความ "บันทึกไม่สำเร็จ" ใช้ทั้งตอนเปลี่ยนเป็น Not proceeding และตอนเปลี่ยนกลับเป็น In care เพราะอยู่ในฟังก์ชันเดียวกัน (`changeStatus` บรรทัด 388)
- **ไม่เปลี่ยน:**
  - แถบ "Could not load data" ตอนโหลดลีดไม่สำเร็จ ยังใช้ข้อความเดิม เพราะเป็นการโหลดจริง
  - ลีดที่บันทึกเหตุผลไว้แล้วแสดงผลเหมือนเดิม ข้อมูลเดิมไม่เกิน 500 ตัวอยู่แล้ว เพราะ API ตรวจมาตลอด
  - เนื้อความใต้หัวข้อยังมาจาก `localizedError` เหมือนเดิม: หน้าภาษาไทยเห็นข้อความกลางที่แปลแล้ว ส่วนหน้าภาษาอังกฤษถ้าบันทึกล้มด้วยเหตุผลอื่น (เช่น API ปฏิเสธ) ยังอาจเห็นข้อความดิบของ API ได้ แต่กรณีเกิน 500 ตัวเกิดจากหน้าจอไม่ได้แล้ว

## ฝาก QA ตรวจ

1. รัน `e2e/web-api/tests/web-ui-write/lead-room-limits.write.spec.ts` ข้อ "the lost reason box stops at the 500 characters the API accepts" ควรขึ้น "Expected to fail, but passed" แล้วถอดป้าย `@known-bug`
2. พิมพ์หรือวางข้อความยาว ช่องหยุดที่ 500 ตัว ตัวนับขึ้น `500/500` กดยืนยันแล้วลีดเปลี่ยนเป็น Not proceeding
3. ตัวนับต้องตรงกับจำนวนตัวอักษรในช่องเสมอ ทั้งตอนพิมพ์และตอนเปิดช่องครั้งใหม่ (ช่องเริ่มจากเหตุผลเดิมของลีดถ้ามี เช่น เปลี่ยน Not proceeding → In care → Not proceeding ช่องจะว่าง ตัวนับเป็น `0/500`)
4. ทำให้การเปลี่ยนสถานะล้ม (เช่น ปิดเน็ตแล้วกดยืนยัน) หัวข้อความต้องเป็น "บันทึกไม่สำเร็จ" / "Could not save lead" ไม่ใช่ "Could not load data"
5. **แอปมือถือ:** ลองข้อ 2-4 บนมือถือด้วย เพราะใช้หน้าจอเดียวกัน
