## ข้อความที่หน้า login แสดงตอนนี้

ใช้เลขเคสเดียวกับตารางใน `nestyk-login-error-cases-for-qa-2026-11-09.md`

| ข้อความ | เคส | ไทย | อังกฤษ |
| --- | --- | --- | --- |
| รหัสผิด (`mobile.auth.invalidCredentials`) | 3, 16 | อีเมลหรือรหัสผ่านไม่ถูกต้อง | Invalid email or password |
| เชื่อมต่อไม่ได้ (`mobile.auth.networkError`, ใหม่) | 9, 11, 12 | เชื่อมต่อระบบไม่ได้ในขณะนี้ กรุณาตรวจสอบอินเทอร์เน็ตหรือลองใหม่อีกครั้งในอีกสักครู่ | Can't connect right now. Check your internet connection or try again in a moment. |
| ยังไม่ได้ยืนยันอีเมล (`mobile.auth.emailNotConfirmed`, ใหม่) | 4 | กรุณายืนยันอีเมลก่อนเข้าสู่ระบบ | Please verify your email before signing in. |
| ลองบ่อยเกินไป (`mobile.auth.tooManyAttempts`, ใหม่) | 6 | ลองหลายครั้งเกินไป กรุณารอสักครู่แล้วลองใหม่ | Too many attempts. Please wait a moment and try again. |
| ข้อความกลาง (`common.errorGeneric`) | 5, 7, 8, 10, 13, 14, 15 และกรณีอื่นทั้งหมด | เกิดข้อผิดพลาด กรุณาลองอีกครั้ง | Something went wrong. Please try again. |

ภาษาจีนและญี่ปุ่นของ 3 ข้อความใหม่

| ข้อความ | จีน | ญี่ปุ่น |
| --- | --- | --- |
| เชื่อมต่อไม่ได้ | 暂时无法连接。请检查网络连接，或稍后再试。 | 現在接続できません。インターネット接続を確認するか、しばらくしてからもう一度お試しください。 |
| ยังไม่ได้ยืนยันอีเมล | 请先完成邮箱验证再登录。 | メールアドレスの認証を完了してからログインしてください。 |
| ลองบ่อยเกินไป | 尝试次数过多，请稍后再试。 | 試行回数が多すぎます。しばらく待ってからもう一度お試しください。 |

- **ญี่ปุ่น:** ข้อความ "ยืนยันอีเมล" และ "ลองบ่อยเกินไป" ใช้ตามที่ Aof ตรวจ ส่วนข้อความ "เชื่อมต่อไม่ได้" แปลใหม่ตามคำที่ QA ปรับ **ขอให้ Aof ตรวจอีกรอบ**
- **จีน:** ยังเป็นร่าง รอคนตรวจ ข้อความ "ยืนยันอีเมล" ปรับเป็น 完成邮箱验证 (ทำการยืนยันให้เสร็จ) ให้ความหมายตรงกับภาษาญี่ปุ่นที่ QA ปรับ

## สิ่งที่แก้

1. **`apps/consumer-app/lib/auth/auth-error.ts:40`:** เพิ่ม `signInErrorKind` แยกสาเหตุการ login ไม่ผ่านเป็น 5 แบบ
    - `invalidCredentials`: Supabase ตอบ `invalid_credentials` หรือ dev login ปฏิเสธ
    - `network`: `NETWORK_ERROR` จาก `lib/api.ts`, `AuthRetryableFetchError` จาก Supabase, `TypeError` จาก fetch หรือ status 5xx จาก Supabase หรือ `POST /auth/sync` (รวมหน้า error HTML จาก proxy)
    - `emailNotConfirmed`: `email_not_confirmed`
    - `rateLimited`: `over_request_rate_limit` หรือ status 429
    - `generic`: นอกนั้นทั้งหมด
2. **`apps/consumer-app/app/login.tsx:126-133`:** แต่ละแบบใช้ข้อความของเราหนึ่งข้อความ เลิกใช้ `localizedError` กับการ login ด้วยอีเมล จึงไม่มีข้อความดิบหลุดไม่ว่าหน้าภาษาอะไร
3. **`packages/i18n`:** เพิ่ม `mobile.auth.networkError`, `emailNotConfirmed`, `tooManyAttempts` ครบ 4 ภาษา และใน `types.ts`

## ผลกระทบ

- **ทั้งเว็บและแอปมือถือ:** หน้า login ใช้ไฟล์เดียวกัน
- **หน้าอังกฤษ:** เคส 4 และ 6 เปลี่ยนจากข้อความของ Supabase เป็นข้อความของเรา เคส 5, 7, 8, 10, 13–15 เปลี่ยนจากข้อความดิบเป็นข้อความกลาง
- **หน้าไทย:** เคส 4, 6, 9, 11, 12 เปลี่ยนจากข้อความกลางเป็นข้อความเฉพาะ ที่เหลือเหมือนเดิม
- **ไม่เปลี่ยน:** ปุ่ม Google/Facebook บนหน้า login (ยังปิดอยู่) ยังใช้ `localizedError` แบบเดิม

## หน้าสมัครและหน้าลืมรหัสผ่าน (QA ข้อ 3)

ใช้กฎเดียวกับหน้า login: แสดงเฉพาะข้อความของเรา ไม่ส่งต่อข้อความดิบจาก Supabase หรือ API ไม่ต้องเพิ่มคำแปล ใช้ key ที่มีอยู่แล้ว

| จุด | ไฟล์ | ข้อความที่แสดง |
| --- | --- | --- |
| กดสมัคร | `apps/consumer-app/app/register.tsx:130` | กรณีพิเศษเดิมคงไว้ (ยังไม่ได้ตั้งค่า Supabase, สมัครแบบทดสอบใช้ไม่ได้, API ตอบสมัครไม่สำเร็จ) / เชื่อมต่อไม่ได้ → `networkError` / บ่อยเกิน → `tooManyAttempts` / นอกนั้น → สมัครสมาชิกไม่สำเร็จ… |
| ใส่รหัส 6 หลัก | `register.tsx:151` | รหัสผิดหรือหมดอายุ → รหัสไม่ถูกต้อง… / เชื่อมต่อไม่ได้ → `networkError` / บ่อยเกิน → `tooManyAttempts` / นอกนั้น (รวม API sync ล้มหลังยืนยันรหัส) → ข้อความกลาง |
| ส่งรหัสใหม่ | `register.tsx:174` | เชื่อมต่อไม่ได้ → `networkError` / บ่อยเกิน → `tooManyAttempts` / นอกนั้น → สมัครสมาชิกไม่สำเร็จ… |
| ขอลิงก์รีเซ็ต | `apps/consumer-app/app/reset-password.tsx:97` | เชื่อมต่อไม่ได้ → `networkError` / บ่อยเกิน → `tooManyAttempts` / นอกนั้น → ข้อความกลาง |
| ตั้งรหัสใหม่ | `reset-password.tsx:136` | ลิงก์ใช้ไม่ได้ → ข้อความเดิม / เชื่อมต่อไม่ได้ → `networkError` / บ่อยเกิน → `tooManyAttempts` / นอกนั้น → ข้อความกลาง |

- กติกาอยู่ที่ `authErrorText` ใน `apps/consumer-app/lib/auth/auth-error.ts` ใช้ตัวแยกสาเหตุตัวเดียวกับหน้า login "ส่งอีเมลบ่อยเกิน" (`over_email_send_rate_limit`) นับเป็นบ่อยเกินด้วย เพราะ Supabase ตอบ 429
- **ข้ามไว้:** ปุ่ม "สมัครด้วย Google / Facebook" บนหน้าสมัคร (`register.tsx` ส่วนปุ่ม social) ยังส่งต่อข้อความดิบแบบเดิม ปุ่มนี้ไม่ได้เช็ก flag `EXPO_PUBLIC_ENABLE_SOCIAL_LOGIN` เหมือนหน้า login จึงกดได้และ error จริงตอน provider ปิดอยู่ จะคุยกับ Mos แยก
- **ผลกระทบหน้าอังกฤษ:** ข้อความของ Supabase ที่เคยเห็น เช่น captcha ไม่ผ่าน, ปิดรับสมัคร, รหัสใหม่ซ้ำของเดิม กลายเป็นข้อความของเรา "รหัสใหม่ซ้ำของเดิม" จะได้ข้อความเฉพาะหลัง launch ตามที่ตกลงไว้
- **แก้เทสเดิม 1 ข้อ:** `apps/consumer-app/components/registration.test.cjs` ข้อ "a signup rejection stays on the form with feedback" เดิมตรวจว่าหน้าจอแสดงข้อความดิบ "Email already registered" ตอนนี้ตรวจว่าแสดง "สมัครสมาชิกไม่สำเร็จ…" และไม่มีข้อความดิบ (ข้อความนี้มาจากการสมัครแบบทดสอบใน dev build เท่านั้น)

## คำถามของ QA

**สมัครซ้ำด้วยอีเมลที่ยังไม่ยืนยัน ได้รหัส 6 หลักใหม่ไหม:** จากโค้ด (`AuthContext.tsx` ส่วน `signUp`) ถ้า Supabase ไม่ตอบ error และไม่ให้ session แอปจะพาไปหน้าใส่รหัสเหมือนสมัครครั้งแรก แต่ยังไม่ได้ทดสอบกับ Supabase ของเราว่าจะส่งรหัสใหม่จริงไหม และรหัสผ่านที่กรอกตอนสมัครซ้ำจะทับของเดิมหรือไม่ จะทดสอบแล้วแจ้ง ถ้าได้ จะเพิ่มคำแนะนำนี้ในข้อความเคส 4

## ฝาก QA ตรวจ

1. e2e ที่ QA วางแผนไว้ (จำลองด้วย `page.route`) ตรวจข้อความตามตาราง "ข้อความที่หน้า login แสดงตอนนี้"
2. เคส 12: ตอบ 502 เป็น HTML ต้องได้ข้อความ "เชื่อมต่อไม่ได้" ไม่ใช่ข้อความกลาง
3. เคส 13: ดูว่าแถบ "session หมดอายุ" ขึ้นบนหน้า login หรือไม่
4. ตรวจภาษาญี่ปุ่นของข้อความ "เชื่อมต่อไม่ได้" (แปลใหม่)
5. หน้าสมัครและหน้าลืมรหัสผ่าน: จำลอง captcha ไม่ผ่าน, 429 และ API sync ล้มหลังยืนยันรหัส 6 หลัก (ข้อความ master_roles) ต้องไม่มีข้อความดิบบนหน้าอังกฤษ
