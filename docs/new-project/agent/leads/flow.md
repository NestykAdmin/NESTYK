## 1. สรุป

Agent บันทึกทุกคนที่สนใจห้องเป็น **lead** — ไม่ต้องรอทำสัญญา  
ตัวอย่าง: ห้อง A มีคนมาดู 10 คน → **`leads` 10 แถว** สถานะต่างกันได้

## 2. Status pipeline

| Status | ความหมาย | ใครตั้ง |
|--------|----------|---------|
| `new` | ใหม่ — เพิ่งสร้าง | อัตโนมัติตอนสร้าง |
| `inprogress` | กำลังดูแล | Agent เลือกเอง |
| `lost` | ไม่ไปต่อ | Agent เลือก + เหตุผล |
| `booked` | จองแล้ว — พร้อม/กำลังทำสัญญา | อัตโนมัติเมื่อ promote เป็น tenant |

```
new → inprogress ──→ booked ──→ (สร้าง tenant + สัญญา)
         │              │
         └────→ lost    └── lead ยังอยู่ · status = booked
```

**สถานะที่แสดง "นัดดูห้อง"** (`viewing`, สีม่วง) — **ไม่เก็บใน `leads.status`** คำนวณจาก `nextViewingAt` (นัด `scheduled` ที่ใกล้ที่สุดและยังไม่ถึงเวลา ใน `lead_viewings`): ลีด `new` / `inprogress` ที่มีนัดจะแสดงป้าย "นัดดูห้อง" พร้อมวันเวลาและห้องที่นัด และกลับเป็นสถานะเดิมเองเมื่อเลยเวลานัดหรือยกเลิกนัด · หน้ารายละเอียดลีดแสดงรายการนัดทั้งหมดของลีด (นัดได้หลายห้อง) เหนือ "ห้องแนะนำเพิ่มเติม" — ดู [viewings.md](./viewings.md)

**ชิปสถานะในหน้ารายการลีด** (ใต้ช่องค้นหา · `MobileFilterChip` ทรงสี่เหลี่ยมมุมมน 12 แบบเดียวกับชิปกรองหน้าลูกค้า): ทั้งหมด · ใหม่ · กำลังดูแล · นัดดูห้อง · จองแล้ว · ไม่ไปต่อ พร้อมจำนวน — เลือกได้ทีละสถานะ (แตะซ้ำ = ทั้งหมด) ใช้ร่วมกับตัวกรองทำเลได้ · กรองตาม**สถานะที่แสดง** จึงตรงกับป้ายในแถวเสมอ · จำค่าไว้เมื่อเปิดลีดแล้วกลับมา · สีชิปตามสถานะ ชุดเดียวกับป้ายในแถว (`leadStatusTone` + `STATUS_PILL_TONES`): ไม่ได้เลือก = พื้นตาม theme ขอบเทา + จุดสีสถานะ 8px (`tone.dot` สีกลางที่สด เฉดเดียวกับพื้นป้าย — ไม่ใช้ `tone.fg` ที่เข้มจนเหลืองดูเป็นน้ำตาล) · เลือกอยู่ = พื้นอ่อน ขอบและตัวหนังสือสีเข้มของสถานะ · "ทั้งหมด" ใช้โทนเทา ไม่มีจุด — API: `status` และ `statusCounts` ใน [api.md](./api.md)

**วงแหวนผลจับคู่ในแถวรายการลีด** (`MobileScoreRing`) — 4 แบบ แยกด้วยไอคอนและสี ไม่ใช่แค่คำใต้วง (ข้อมูลไม่พอไม่ใช้วงแหวน เพราะยังไม่มีอะไรให้วัด):

| กรณี | วงแหวน | ตรงกลาง | ป้ายใต้วง | บรรทัดล่าง |
|---|---|---|---|---|
| ยังไม่จับคู่ | เส้นประ เทา | ✦ เทา (สีข้อความรอง) | ยังไม่จับคู่ | — |
| ข้อมูลไม่พอ (ไม่มีงบสูงสุด / หมุด) | **ไม่ใช่วงแหวน** — วงกลมพื้นเหลืองอ่อน `#FEF3C7` | ⚠ ส้ม | ข้อมูลไม่พอ | — |
| จับคู่แล้ว 0 ห้อง (`lastMatch.resultCount = 0`) | แดงอ่อน `#FEE2E2` | ✕ แดง | ไม่พบห้อง | — |
| จับคู่แล้ว | ตามคะแนน แดง / เหลือง / เขียว | ตัวเลข % | ตรงกัน | ตรง N ห้อง |

ลีดที่มีนัดดูห้องที่ยังไม่ถึงเวลา แสดงกล่องวันเวลาแทนวงแหวน

**การเรียงเริ่มต้น = อัปเดตล่าสุด** (`updated_desc`) — ลีดที่เพิ่งมีความเคลื่อนไหวขึ้นบนสุด: แก้ไขข้อมูล · เปลี่ยนสถานะ · บันทึกการตั้งค่าจับคู่ · กดจับคู่ห้อง · นัดดูห้อง · เลื่อน / ยกเลิก / แก้หมายเหตุนัด ทุกอย่างขยับ `leads.updated_at` (ล้างผลจับคู่ไม่ขยับ)

## 3. Lead → Tenant (เมื่อทำสัญญา)

**กฎ:** แถว lead **ไม่ลบ** — อัปเดตเป็น `booked` และผูก tenant

```
Lead (inprogress)
    │ Agent กดทำสัญญา / จอง
    ▼
Lead.status = booked
Lead.tenant_id = {new tenant id}
    │
    ▼
INSERT tenants (lead_id, name, phone, …)   ← ชื่ออยู่ทั้ง lead และ tenant
    │
    ▼
POST /agent/contracts (roomTenancyId / จาก tenant)
```

หลัง promote:

| ที่เก็บ | มีชื่อ contact | หมายเหตุ |
|---------|----------------|----------|
| `leads` | ✅ | `status = booked`, `tenant_id` ชี้ tenant |
| `tenants` | ✅ | แถวใหม่ — ลูกบ้นตามสัญญา |

Lead อีก 9 คน → คงเป็น `inprogress` / `lost` — **ไม่มี** แถวใน `tenants`

ในแอป การจองคือ `POST /agent/tenants` ผ่านแผ่นยืนยันเดียวกัน (`ReserveRoomSheet`) สองทาง: ปุ่ม **จองห้องนี้** ในหน้าห้องที่จับคู่ของลีด ([viewings.md](./viewings.md)) และปุ่ม + ในเมนูลูกค้า (เลือกลีด → เลือกห้อง) · ทุก response ของลีดมี `tenantId` และ `rentRoomId` (`null` จนกว่าจะจอง) · หน้ารายละเอียดลีดที่ `booked` มีปุ่ม **ดูผู้เช่าและสัญญา** ไปหน้าผู้เช่า

## 4. Lead อื่นในห้องเดียวกัน

เมื่อ lead หนึ่งเป็น `booked` / มีสัญญา active:

- Lead คนอื่น → แนะนำตั้งเป็น `lost` (optional bulk / manual)
- ห้องมี tenant active ได้คนเดียว (ดู contracts pack)
- ห้องหนึ่งมีลีด `booked` ได้คนเดียว (index `uq_leads_one_booked_per_room`): จองซ้ำ `POST /agent/tenants` ตอบ 409 `ROOM_ALREADY_BOOKED` · รายการเลือกห้องบอกชื่อผู้จองและกดไม่ได้ · ห้องที่จองแล้วไม่ถูกนำมาจับคู่ให้ลีดอื่น (`matchCandidates`)
