## 1. หน้าจอ

หน้าห้องที่จับคู่ได้ (tab `leadRoom`) แสดงตามนัดของห้องนี้ (`status = scheduled` ล่าสุด ไม่แยกว่าเลยเวลานัดแล้วหรือยัง):

| ห้องนี้ | banner ด้านบน | แถบปุ่มล่าง |
|---|---|---|
| ยังไม่มีนัด / ยกเลิกแล้ว | — | **นัดดูห้อง** (พื้นเหลือง เต็มความกว้าง) |
| มีนัด | "นัดดูห้องแล้ว · 5 ต.ค. 14:00" (พื้นม่วงอ่อน เตือนอย่างเดียว กดไม่ได้) | **แก้ไข/ยกเลิกนัด** (ขอบเหลือง) + **จองห้องนี้** (พื้นเหลือง) |

- **แก้ไข/ยกเลิกนัด** เปิดแผ่นเดิมเพื่อเลื่อนนัด หรือยกเลิก (ยืนยันในแผ่น) · ยกเลิกแล้ว banner หาย ปุ่มกลับเป็นนัดดูห้อง
- **จองห้องนี้** เปิดแผ่นยืนยันในหน้าเดิม (`ReserveRoomSheet`) ไม่สลับเมนู
  - แผ่นแสดงลูกค้ากับห้อง · เลขห้องและสถานะจองอ่านจาก `GET /agent/tenants/rooms?leadId=&roomId=` ตอนเปิด
  - ถามสองช่อง: อีเมล (ดึงจากลีด ไม่บังคับ ถ้าว่างจะเตือนว่าต้องใช้ตอนทำหนังสือจอง) และเลขบัตร/พาสปอร์ต · ชื่อ เบอร์ สัญชาติ หมายเหตุ ดึงจากลีด อยู่หลังลิงก์ "แก้ไขชื่อ เบอร์โทร และข้อมูลอื่น" · ข้อความผิดพลาดขึ้นใต้ช่อง ตรวจด้วยกฎของ API (`lib/tenant-profile.ts`)
  - **ยืนยันจอง** เรียก `POST /agent/tenants` · ลีดเป็น `booked` (API สร้างผู้เช่าทำให้เอง)
  - จองแล้วแผ่นเปลี่ยนเป็น "จองแล้ว": **ทำหนังสือจองต่อ** ไปหน้าผู้เช่าและเปิดฟอร์มหนังสือจองทันที (ยังไม่มีอีเมล ปุ่มเป็น **ไปหน้าข้อมูลผู้เช่า**) · **ไว้ทีหลัง** ปิดแผ่น · ย้อนกลับจากหน้าผู้เช่ากลับมาหน้าห้องนี้
  - ห้องที่ลีดอื่นจองแล้ว: แผ่นบอกชื่อผู้จองและยืนยันไม่ได้ · จองชนกัน API ตอบ 409 `ROOM_ALREADY_BOOKED`
- banner กับแถบปุ่มใช้ข้อมูลชุดเดียวกัน (`useLeadRoomViewing` ใน shell) แก้หรือยกเลิกนัดแล้วอัปเดตทั้งคู่ทันที · ระหว่างโหลดนัด ปุ่มถูกปิดไว้ก่อน
- ลีดที่ `booked` หรือ `lost` ปุ่มถูกปิด · ลีดที่จองห้องนี้เอง แถบปุ่มเหลือปุ่มเดียว **ดูผู้เช่าและสัญญา** (ไปหน้าผู้เช่า ย้อนกลับแล้วกลับมาหน้านี้)
- ดูรายละเอียดห้องยังทำได้จากการแตะรูป และเมนู ⋯ (เปิด modal เต็มจอ)

**แผ่นเลือกเวลา** (ไล่จากบนลงล่าง):

แบบแถวฟอร์ม (แบบหน้าเพิ่มนัดของแอปปฏิทินในระบบ) กางได้ทีละแถว:

1. **วันที่** — แสดง "ส. 4 ต.ค. 2569" กดแล้วกางปฏิทินเต็มเดือน (`react-native-calendars`) ใต้แถว วันที่ผ่านแล้วกดไม่ได้ เลือกแล้วพับเก็บเอง
2. **เวลา** — `@react-native-community/datetimepicker` ทีละ 15 นาที: iOS กางวงล้อใต้แถว · Android เปิดหน้าปัดนาฬิกาของระบบ (ปัดเศษเป็นช่วง 15 นาที) · เว็บกาง `<input type="time">` (`ViewingTimeField.web.tsx`)
3. เวลาที่ผ่านแล้ว: เตือนสีแดง บันทึกไม่ได้ · ห่างจากนัดอื่นในวันเดียวกันไม่ถึง 1 ชั่วโมง: เตือนสีส้ม ยังบันทึกได้ — ห้องอื่น "ช่วงเวลานี้คุณมีนัดคนอื่นแล้ว (17:00)" · ห้องเดียวกัน "ห้องนี้มีนัดดูช่วงเวลานี้แล้ว (17:00)" (เช็กเฉพาะนัดของ agent คนนี้)
4. **นัดอื่นในวันเดียวกัน** — ดึง `GET /agent/viewings` ของวันที่เลือก (ไม่รวมนัดที่กำลังแก้ และนัดที่ยกเลิก)
5. หมายเหตุ · ปุ่มบันทึก · ลิงก์ยกเลิกนัด (เฉพาะนัดเดิม)

นัดใหม่เริ่มที่ชั่วโมงเต็มถัดไป (เช่น ตอนนี้ 17:20 → 18:00) · เลื่อนนัดเริ่มที่เวลาเดิม

## 3. API (`@Roles('agent')`)

| Method | Path | หมายเหตุ |
|--------|------|----------|
| `POST` | `/agent/leads/:id/viewings` | `{ rentRoomId, scheduledAt, note? }` → `LeadViewing` (201) |
| `GET` | `/agent/leads/:id/viewings` | ทุกนัดของลีด เรียงตามเวลา |
| `GET` | `/agent/viewings?from=&to=` | นัดของ agent ในช่วง (ไม่เกิน 62 วัน) ไม่รวม `cancelled` |
| `PATCH` | `/agent/viewings/:id` | `{ scheduledAt?, status?, note? }` อย่างน้อยหนึ่งฟิลด์ |

Validation (400): `scheduledAt` ต้องเป็นอนาคต (เผื่อ 60 วินาที) และไม่เกินหนึ่งปี · `note` ไม่เกิน 500 ตัวอักษร

| สถานะ | กรณี |
|-------|------|
| 404 | ลีด / ห้อง / นัด ไม่ใช่ของ agent นี้ |
| 409 `LEAD_CLOSED` | ลีด `booked` หรือ `lost` |
| 409 `VIEWING_EXISTS` | มีนัดห้องนี้ที่ยังไม่ถึงเวลาอยู่แล้ว (ส่ง `viewingId` กลับ) |
| 409 `VIEWING_CLOSED` | เลื่อนเวลา / เปลี่ยนสถานะของนัดที่ไม่ใช่ `scheduled` (แก้หมายเหตุได้เสมอ) |

`LeadViewing`: `{ id, leadId, leadName, rentRoomId, roomTitle, roomNumber, scheduledAt, status, note, createdAt }` — `roomTitle` = ชื่อโครงการ หรือชื่อประกาศ หรือ `#id`

## 4. สถานะ "นัดดูห้อง" ของลีด

ทุก response ของลีด (`GET /agent/leads`, `GET /agent/leads/:id`, แก้ไข, เปลี่ยนสถานะ) มี `nextViewingAt` = เวลานัด `scheduled` ที่ใกล้ที่สุดซึ่งยังไม่ถึงเวลา และ `nextViewingRoom` = ห้องของนัดนั้น ("ชื่อโครงการ · เลขห้อง") — `null` ทั้งคู่ถ้าไม่มีนัด · คำนวณด้วย `loadNextViewings` (`DISTINCT ON (lead_id) … ORDER BY lead_id, scheduled_at` join ห้องและโครงการ) ไม่มีคอลัมน์ใหม่ใน `leads`

แอป (`leadDisplayStatus`): ลีด `new` / `inprogress` ที่ `nextViewingAt` อยู่ในอนาคต แสดงป้ายม่วงอ่อน **"นัดดูห้อง"** (ป้ายไม่มีเวลา) — เลยเวลานัดหรือยกเลิกแล้วกลับเป็นสถานะเดิมเอง · เมนูเปลี่ยนสถานะยังใช้ `leads.status` จริง · บันทึก/เลื่อน/ยกเลิกนัดแล้วโหลดลีดใหม่ทันที

วันเวลานัดใช้สีแบรนด์ ตัวเข้มบนพื้นสว่าง (ไม่ใช้ม่วงบนม่วง):

| ที่แสดง | รูปแบบ |
|---|---|
| รายการลีด — กล่องแทนวงแหวน % (`ViewingDateTile.tsx` ใช้ร่วมกับหน้ารายละเอียด) | แถบบน "วันนี้" / "พรุ่งนี้" / วันในสัปดาห์ (ภายใน 6 วัน) / "อีก N วัน" (นัดที่ผ่านแล้วแสดงวันในสัปดาห์) · เวลาหนา 18 สีหัวข้อ · วันที่ 12 สีรอง · สีตาม theme (โหมดมืดอ่านได้) · นัดวันนี้: แถบและขอบเหลือง `#F8B615` ตัวดำ |
| รายการลีด — บรรทัดล่าง | ชื่อห้องที่นัด แทนจำนวนห้องที่จับคู่ได้ |
| หน้ารายละเอียดลีด — ส่วน "นัดดูห้อง (N)" | ดูด้านล่าง |
| หน้าข้อมูลเต็ม (`LeadNextViewingLine`) | ไอคอนปฏิทิน + "วันนี้ · 5 ต.ค. 17:00" ตัวดำหนา 13 + " · ห้อง" สีรอง |

**หน้ารายละเอียดลีด** (`LeadViewingsSection.tsx`): ดึง `GET /agent/leads/:id/viewings` แสดง**ทุกนัด**ของลีด (นัดได้หลายห้อง ห้องละ 1 นัดที่ยังไม่ถึงเวลา) อยู่ระหว่างปุ่ม "ดูข้อมูลทั้งหมด" กับห้องที่จับคู่ · ไม่มีนัดเลย = ไม่แสดงส่วนนี้

- เรียง: นัดที่ยังไม่ถึงเวลา (ใกล้สุดก่อน) แล้วนัดที่ผ่านมา (ล่าสุดก่อน)
- แถว: กล่องวันเวลา · ชื่อห้อง · "ห้อง 1208" · หมายเหตุ 1 บรรทัด — **ไม่มีป้ายสถานะ** สีของกล่องวันเวลาบอกสถานะแทน (`ViewingDateTile` prop `tone`):
  - ยังไม่ถึงเวลา: แถบชื่อวันและขอบ**เหลือง** ตัวเลขเวลาสีเข้ม
  - ผ่านเวลาแล้ว (`scheduled` ที่เลยเวลา หรือ `done`): แถบชื่อวัน**เทา** ตัวเลขเวลาสีเทา
  - `cancelled`: กล่องเทา ขีดฆ่าตัวเลขเวลา ทั้งแถวจาง
  - ชื่อสถานะยังอ่านได้ผ่าน screen reader (`viewing.statuses`)
- หน้ารายการลีดใช้กล่องเดียวกันแบบไม่ส่ง `tone`: เหลืองเฉพาะนัดวันนี้ (หน้านั้นมีแต่นัดที่ยังไม่ถึง)
- แตะ: ห้องอยู่ในผลจับคู่ → เปิดหน้าห้องที่จับคู่ (เลื่อน / ยกเลิก / นัดใหม่) · ไม่อยู่ในผลจับคู่และยังไม่ถึงเวลา → เปิดแผ่นเลื่อน/ยกเลิกนัดตรงนี้ · นอกนั้นแตะไม่ได้
- ห้องที่จับคู่ได้ซึ่งมีนัด (ไม่นับนัดที่ยกเลิก) ย้ายออกจากรายการห้อง ส่วนที่เหลือใช้หัวข้อ **"ห้องแนะนำเพิ่มเติม (N)"** · ไม่มีนัด = หัวข้อเดิม "ห้องที่จับคู่ (N)" · ถ้าทุกห้องมีนัดแล้ว แสดง "ห้องที่จับคู่ได้มีนัดดูครบแล้ว"
- ลีดที่มีนัด: ส่วน "ห้องแนะนำเพิ่มเติม" **เริ่มแบบหุบ** — หัวส่วนเป็นหัวข้อเปล่าแบบ "นัดดูห้อง (N)" และ**เหมือนกันทั้งตอนหุบและกาง**: "ห้องแนะนำเพิ่มเติม (8)" (จำนวนทั้งหมดเสมอ) · บรรทัด "สูงสุด 95% · ล่าสุด 5 ต.ค. 14:20" + ป้ายเหลือง "ข้อมูลลีดเปลี่ยน" ถ้าผลจับคู่เก่า (แทนบรรทัดเวลาจับคู่ในเนื้อหา) · ⚙ ⓘ · ลูกศร — แตะหัวข้อหรือลูกศรเพื่อกาง/หุบ · animation (`react-native-reanimated`): ลูกศรหมุน 200ms · เนื้อหา `FadeIn` 200ms / `FadeOut` 150ms · ความสูงส่วน `LinearTransition` 220ms · การ์ด 3 ใบแรก `FadeInDown` ไล่ทีละ 40ms · เปลี่ยนลีดแล้วกลับเป็นหุบ · ลีดที่ไม่มีนัดเปิดตามเดิม · การ์ดสถานะ (ยังไม่จับคู่ / ข้อมูลไม่พอ / โหลดไม่สำเร็จ / ไม่พบห้อง / มีนัดครบแล้ว) ไม่หุบ
- หัวลีดไม่มีบรรทัดนัดถัดไปแล้ว (ซ้ำกับส่วนนัดดูห้อง)
